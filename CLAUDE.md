# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build & test

Two-process project: Go daemon under `server/`, TypeScript MCP proxy under `client/`. Requires Go 1.27+ and Node 18+. The Makefile also runs on native Windows under GNU make: `OS=Windows_NT` selects `.exe` and `python`, and without `MSYSTEM` (Git Bash) the recipes run in `cmd.exe` through the macro block at the top (`RM_RF`, `CP_FILE`, `SAY`, `XBUILD`, …). Targets never call a shell command directly, so a new recipe must use those macros; the three sibling-binary lookups (`resolveDaemonBin`, the regression suite's `DAEMON`, `_client._resolve_bin`) add `.exe` on Windows.

The Makefile at the repo root is the canonical entrypoint:

```bash
make build            # compile both in-place (server/memstated, client/dist/)
make install          # put `memstated` on GOBIN and `memstate-mcp` on PATH via npm link
make uninstall        # reverse of install
make install-skill    # copy the skills to ~/.claude/skills/{memstate,memstate-precompact} + add UserPromptSubmit hooks
make uninstall-skill  # reverse of install-skill
make test             # go test + go vet (+ vet for the other OS) + TS smoke + MCP regression suite
make release          # memstated for five platforms + the proxy bundle memstate-mcp.tar.gz under dist/
make clean            # remove build artifacts
```

Raw commands for partial work:

```bash
cd server && go build -o memstated .          # Go daemon only
cd client && npm install && npm run build     # TS proxy only
cd server && go test -run TestStoreRoundTrip  # single Go test
node client/dist/index.js --test              # end-to-end: spawn daemon, hit /health, list tools
node client/test/regression.mjs               # full-stack regression: every MCP tool over stdio against a temp DB
```

Running the daemon directly:

```bash
./server/memstated                                       # child mode, random port, banner on stderr
./server/memstated --addr 127.0.0.1:8765                 # shared-daemon mode
./server/memstated --addr 127.0.0.1:8765 --idle-timeout 30m   # long-lived, self-exits when idle
./server/memstated status --addr 127.0.0.1:8765
./server/memstated stop   --addr 127.0.0.1:8765
./server/memstated restart --addr 127.0.0.1:8765         # stop, then start detached with the config /health reported
./server/memstated projects                              # list live projects with memory counts
./server/memstated dump memstate_mcp                     # pretty-print a project's memories (ANSI markdown)
./server/memstated dump --keys memstate_mcp decisions    # keypath tree only, optionally scoped to a subtree
./server/memstated search --project memstate_mcp ollama  # FTS5 search from the CLI (omit --project for all)
./server/memstated export --all                          # full-history JSON to ~/.memstate/exports/
./server/memstated import backup.json                    # timestamp-merge into the local DB
./server/memstated upgrade                               # swap in the latest GitHub release binary; restarts a running shared daemon
./server/memstated --addr 127.0.0.1:8765 --embed-model qwen3-embedding:4b   # pin the embed model by flag (normally: memstated config set MEMSTATE_EMBED_MODEL ...)
./server/memstated config                                # every setting, its source, and whether the running daemon matches
./server/memstated config set MEMSTATE_EMBEDDING_URL http://127.0.0.1:8081/v1   # persist in ~/.memstate/config.env
./server/memstated embed status [--watch] [--probe]      # dashboard: coverage bar per model, sizes, cosine histogram, threshold fit
./server/memstated embed rebuild --model qwen3-embedding:4b   # drop + recompute one model's vectors (direct SQLite, prints progress)
./server/memstated embed prune --keep qwen3-embedding:4b      # delete vectors of every other model
echo '{"session_id":"s1","cwd":"'$PWD'","prompt":"how does the upgrade keep the embed model"}' | ./server/memstated recall   # what the UserPromptSubmit hook prints
```

## Architecture

```
MCP client ──stdio──> client/dist/index.js ──HTTP loopback──> server/memstated ──> SQLite
              (MCP)        (thin TS proxy)                     (Go daemon, REST)
```

**All storage logic (keypath versioning, FTS, conflict detection, tombstones, embeddings) lives in the Go daemon.** The TS proxy (`client/src/index.ts`) exists only to speak MCP — each tool call becomes one HTTP POST. Do not add business logic to the proxy.

Wire protocol between proxy and daemon is REST, not MCP. Daemon routes are declared in `server/http.go` (`newRouter`). MCP tool shape is declared in `client/src/index.ts` (`TOOLS`). Any new tool requires edits in both, plus the Python CLI mirror under `client/skill/scripts/`.

### Settings file (`server/config.go`, `client/src/config.ts`, `_client.py`)

One file, `~/.memstate/config.env` (`MEMSTATE_CONFIG` names another, `MEMSTATE_CONFIG=off` skips it), holds `KEY=VALUE` lines with the `MEMSTATE_*` names everything already reads from the environment. The daemon loads it as the first line of `main()` and exports only the keys the environment does not set, so the precedence `flag > env > config.env > default` falls out of the existing `os.Getenv` calls and no other code knows the file exists. The proxy (`loadConfigFile` before any module-level const) and the Python scripts (`_load_config_file()` at import) apply the same rule, so a proxy-spawned daemon, a hand-started one and the scripts agree. `memstated config` prints every setting with its source (`configSource`) and compares with the running daemon's `/health`; `config set|unset` edit the file (`writeConfigValue` keeps other lines). `memstate-mcp setup` writes `MEMSTATE_EMBED_MODEL` / `MEMSTATE_EMBEDDING_URL` there and never puts settings into agent `args`, which installers rewrite. `/health` carries `pid`, `args` and `config_file`; `restartPlan` replays the old daemon's `args` (minus `--addr`) and pins nothing else, so an edited setting takes effect on `memstated restart` or `upgrade`, and `reportRestartDiff` prints what changed. **Every test or smoke run that spawns the binary or the proxy sets `MEMSTATE_CONFIG=off`** (`runDaemon`, `cli_test`, `upgrade_test`, `regression.mjs`, `SMOKE_ENV`), or the developer's file leaks in. A new setting goes into `configSettings` and the README table.

### Lifecycle model (non-obvious)

Three modes, selected at proxy startup by `ensureDaemon` (`daemonMode` names the result in the `--test` output and the ready line):

- **Shared mode (default):** one daemon per database. The proxy reads `daemon.addr` next to the DB (`readAddrFile`) and attaches when `/health` answers there; otherwise, for the default DB, it probes `DEFAULT_ADDR` (`127.0.0.1:8765`, equal to `defaultAddr` in `server/main.go`) and attaches or spawns a detached daemon there (same path as attach mode). A custom `MEMSTATE_DB` with no published daemon falls to child mode, because the default port belongs to the default DB; so does an alien process on the default port (with a warning). The Python scripts attach through `daemon.addr` too (`_client._published_addr`) and never start a shared daemon. This reversed the 2026-04-21 "random port, 1:1 lifetime" default on 2026-10-07: several clients had each started a daemon, and the recall hook needs a shared one.
- **Child mode (`MEMSTATE_CHILD=1`, or the fallbacks above):** proxy spawns `memstated` on `127.0.0.1:0` (OS-picked port), passes its own PID via `--owner-pid`, and reads the `MEMSTATE_READY addr=<addr>` banner from the daemon's stderr to learn the address. On proxy exit the daemon is SIGTERMed; if the proxy is SIGKILLed, the daemon's 2-second `kill(owner_pid, 0)` loop notices and self-exits.
- **Attach mode (`MEMSTATE_ADDR` set):** proxy probes `/health`. If a memstate daemon answers → attach. If nothing is listening → spawn a **detached** daemon on that addr (no `--owner-pid`, own session) and attach; the daemon outlives the proxy. If a non-memstate process is on the port → hard error. Set `MEMSTATE_IDLE_TIMEOUT` (e.g. `30m`) in the proxy's env to have the lazy-spawned daemon self-exit after idleness.
- **Embed flags still flow through the proxy.** `parseEmbedOptions` in `client/src/index.ts` reads `--embed-model` / `--embedding-url` / `--embed-timeout` from the proxy argv (flag beats env, and env includes config.env; `--ollama-url` and `MEMSTATE_OLLAMA_URL` are deprecated aliases that print one notice) and `embedDaemonArgs` renders them as daemon flags on every spawn, child or detached. This is the legacy path: `memstate-mcp setup [--embed-model NAME] [--embedding-url URL]` writes config.env and puts only the entry path into agent `args`, listing the models the configured server serves when interactive. On attach the proxy compares its model with the daemon's `embed_model` from `/health` and warns on mismatch.
- **Detached MEMSTATE_DB warning:** the proxy only warns that `MEMSTATE_DB` is ignored when it *attached* to an already-running daemon. When it lazy-spawns, the child inherits env, so the warning would be wrong — tracked via the `alreadyRunning` flag in `attach()`.

A manually-started `--addr` daemon that finds the port busy probes `/health` itself: if occupant is ours → exit 0 quietly; otherwise exit 2 loudly. The proxy translates exit 2 from a lazy-spawn into a readable "port occupied by non-memstate" error.

### Idle-exit (`server/main.go`)

`--idle-timeout` (env `MEMSTATE_IDLE_TIMEOUT`) wraps the router in `activityMiddleware` that stamps `lastActivity` on every request; a `watchIdle` goroutine polls and triggers `shutdownFn` once no request has arrived for the timeout. Disabled when `--owner-pid` is set (parent already owns our lifetime). Poll interval is `timeout/4` clamped to `[5s, 60s]`.

### Versioned keypath store (`server/store.go`)

- Data model: per-project dot-notation keypath tree. Each write appends a new row to `memories` (never updates). Write responses (`writeResp`, `extractedItem`) carry `MemoryRef`s, never content: the caller knows what it sent, and the superseded version carries a `preview` of `previewWordCount` (40) words. Search hits (`searchResult`) likewise carry `preview` and add `content` only when the request sets `include_content` (the CLI and `memstated recall` do); the MCP tool does not expose it, so the model reads full text with `memstate_get`. `defaultSearchLimit` is 10.
- Identical content AND metadata (category/topics) to current version is a no-op → `action: "unchanged"`, no new row. Same content with different metadata DOES version.
- `Delete` appends a tombstone row; history is preserved. `ProjectDeleted` gates reads and deletes only — **any write revives a soft-deleted project** (`ensureProject`'s `ON CONFLICT ... SET deleted_at = NULL`).
- FTS5 virtual table `memories_fts(content, keypath, project_id)` backs the `fts` mode and the FTS side of `hybrid`; only the current version is indexed (the superseded version's FTS row is deleted on write). Free-text queries are token-quoted (`ftsQuote`, implicit AND; `ftsQuoteOr` for hybrid, any token) so punctuation can't hit FTS5 operator syntax, and `ftsMatch` wraps them as `{content keypath}: (...) AND project_id: "<id>"` so a project search visits one project's documents inside FTS5 (before 2026-10-07 every search scanned every project and discarded the rest in SQL: 53% of daemon CPU under load). The SQL `m.project_id = ?` filter stays as the correctness gate because the tokenizer stems ids. `migrateFTSProjectColumn` rebuilds a two-column `memories_fts` from older releases on open; both FTS insert sites (`writeExec`, `mergeKeypath`) write the column.
- `hybrid` is the default search mode (`server/hybrid.go`): `SearchAny` (FTS, OR) and `SemanticSearch` (cosine ≥ threshold) each return a candidate pool of `max(3*limit, 30)`, `rrfFuse` merges them by reciprocal rank fusion (k=60) keyed on project+keypath, and each hit carries `score` + `sources`. When the embedder is nil or the query embed fails, the response is FTS-only with a `degraded` reason; it never returns 5xx for that. Explicit `semantic` mode still returns 503/502.
- Semantic search uses `keypath_embeddings` (one row per `(project, keypath, model)`), where the vector is computed from the **current content** at that keypath — recomputed on content change, deleted on tombstone, healed on an unchanged write if the row is missing (e.g. Ollama was down). The `meta` table's `embed_source` row wipes all vectors on startup when the embedding scheme changes.
- `category` (string) and `topics` (JSON array in TEXT) are per-version columns; `/memories/search` filters on them (topics = match-any, via `json_each`).
- Storage runs on a pool of `storeMaxConns()` connections (2 to 4; SQLite WAL + tuned pragmas in the DSN so every connection has them) with `_txlock=immediate`, so a `Write` (read-latest + insert in one transaction) takes the write lock at BEGIN and concurrent writers queue on `busy_timeout` instead of failing on lock upgrade; reads run on the other connections. Load test 2026-10-07 (`notes.load_test_2026_10_07` in memstate): one connection 1100 mixed req/s, four 2200, eight 2100-2800 for 6+ cores of scheduler spin, hence the cap. `TestConcurrentWritersOneKeypath` and `TestReadsRunDuringWrites` guard the pool.

### Heading extraction (`server/extract.go`)

`memstate_remember` without an explicit keypath runs `ExtractHeadings`, which maps each `##`+ heading to a top-level keypath segment (deeper headings nest via dots; optional `root` request field nests everything under a prefix) and collapses common section names (`## TODOs` → `todo`, `## Files to touch` → `files`, etc.) via `reservedAliases`. Fenced code blocks are ignored when scanning for headings. Pre-heading prose lands under `preamble` (or `<root>.preamble`). The TS proxy derives a default `project_id` from the git repo name (cwd basename outside a repo), slugged snake_case, applied whenever a tool call omits project_id; the Python skill scripts share the same rule via `_client.default_project()`.

### User scope (`server/scope.go`)

One reserved project, `_user` (`userProject`), holds facts about the user and the host that are true in every repo. The line between project memory and user memory is enforced by `checkReservedWrite`, called from `writeExec` (live writes) and `mergeKeypath` (import, whose fresh-chain path inserts rows directly): any project id starting with `_` other than `_user` is refused, and a keypath in `_user` must match `preferences.*`, `profile.*`, `host.<host_slug>.env.*` or `host.<host_slug>.tools.*`. Anything else is `ErrReservedWrite` → HTTP 400 (`writeStatus`), so a heading-split summary with a `## Todo` section rolls back whole. Tombstones skip the gate so old mistakes can be deleted. `host_slug` is the first hostname label through the project slug rule, derived in three places that must agree: `hostSlug()` (Go), `HOST_SLUG` (proxy), `_client.host_slug()` (Python). The proxy exposes the scope as `scope: "user"` on six tools (never a raw `project_id`), folds the pruned `_user` tree into every no-arg `memstate_get` under `user`, and drops other hosts' hits from `scope: "user"` searches; `memstated recall` searches `_user` too, reserves one of its three slots for the best user hit (marked `[user]`, seen-file key prefixed `_user/`), and never lets a user-scope failure hide project hits.

### Session project (`client/src/index.ts`, `server/recall.go`)

The cwd project is the default and the strong prior; nothing is persisted, there is no init step and no binding table. On the first eligible prompt of a session (no seen file yet) `memstated recall` prints a `<memstate-scope cwd_project="…">` block before the recall hits: how the cwd project was derived (git repository, home directory, or plain directory via `repoRoot`), and `projectCandidates` from one extra all-projects hybrid search (cwd project and `_user` dropped; only hits the semantic side returned count, because the FTS side matches any word and "config" alone would nominate unrelated projects; top 3 by semantic hit count), or "matches no other project". A `#scope` marker line in the seen file makes it one-time. The model judges and, when the prompt is clearly about another subject, pins the session with the proxy-only `project_name` (accepted on the six project-scoped tools, reads included). `pinSession` enforces the caution rules: snake_case format, one pin per process (a different name later is an error, `project_id` is the per-call escape), an existing id pins freely, a new id needs `new_project=true` AND must not be a near-duplicate of an existing id (`nearDuplicates`: equal after `normalizeId` strips `_`, digits and a trailing dev/test/tmp/old/new, containment when both ≥4 chars, or Levenshtein ≤1 for short / ≤2 for longer names). Results carry `session_project` while pinned. `stripProxyFields` removes `scope`, `project_name`, `new_project` before the daemon sees a body. `checkWriteTarget` enforces one creation rule on writes (`memstate_set`, `memstate_remember`; `memstate_delete` cannot create a project): a write never creates a project unless it targets the cwd project inside a git repository (`CWD_IN_REPO`) or carries `new_project=true`. That covers the cwd project outside a repository, an explicit `project_id`, and a soft-deleted project, so a revive through MCP now needs the flag (`memstate_delete_project` drops the id from the `knownProjects` cache of positive `/projects` answers). A near-duplicate (`nearDuplicates`) is refused even with the flag; the `memstate` CLI is the human escape. From the home directory (`CWD_IS_HOME`) every default write is refused, and the home directory's slug (`HOME_SLUG`) is refused as a pin or an explicit write target (reads stay open for migration). A system directory gets the same treatment (`systemDirReason`: a filesystem root, anything under `SystemRoot`/`windir`, or a Unix system tree such as `/usr`, `/etc`, `/opt`; never `/tmp` or `/var`, which hold real work and are where CI runs the suite; `CWD_SYSTEM_REASON`), because the Claude desktop app starts MCP servers from `C:\WINDOWS\system32` when it is not itself in a project, which on 2026-10-09 put writes into a `system32` project. The workspace is mutable state (`applyWorkspace`, `WORKSPACE_DIR`): when the MCP client declares the `roots` capability, `server.oninitialized` asks `roots/list` once and re-derives the default from the first `file:` root; the first tool call waits on `rootsReady` (2s cap). The pin file records `WORKSPACE_DIR`, not the process cwd, so the hook's `sameDir` match still works. Ids that start with `_` are refused as `project_id`/`project_name` (`isReservedId`; `memstate_delete_project` still takes the raw id) and hidden from `list_projects`. `checkNewProjectFlag` makes `new_project=true` an error where nothing can be created: a read without `project_name`, `scope="user"`, or the repository's own project. The Python scripts mirror the rule (`_client.check_write_target`, `--new-project`, `near_duplicates`), a second implementation that must agree with the proxy. The scope block carries `exists="true|false"` (`recallProjectExists`), a home-directory sentence (no `exists` there), and a home variant of its rule line so the two never contradict. A pinned session publishes its pin for the hook: `writePinFile` writes `<db dir>/recall/pins/<pid>` ("cwd\nproject\n", removed on exit) and `pinnedProject` in `runRecall` follows the newest file whose PID `processAlive` (platform files) reports alive and whose cwd matches after `sameDir` resolves symlinks, pruning dead ones; the scope block keeps describing the directory. Python scripts and the CLI are one-shot and keep `--project`.

### Embeddings (`server/embed.go`)

Ollama-backed content embeddings are fire-and-forget from the write path via `maybeEmbedContent` → `embedder.inFlight`. `embedWithin` admits calls through two package-level budgets: `embedContentSem` (`embedMaxContent`, 2) for content embeds and the backfill, `embedQuerySem` (`embedMaxQuery`, 4) for `Embed` (search queries), so 1000 writers cannot open 1000 requests against one local model server (that did take a laptop down on 2026-10-07) and a write storm cannot make a search wait the full embed timeout; callers past a budget wait, or give up when their context ends. A URL that ends in `/v1` selects an OpenAI-compatible server instead (llama.cpp server, LM Studio, vLLM): `Embed` posts `{"model","input"}` to `{url}/embeddings` rather than `{"model","prompt"}` to `/api/embeddings`, and `contextOverflow` treats llama.cpp's "too large to process" like Ollama's "context length", so `EmbedDocument` halves for both. Writes succeed even if Ollama is down; errors are throttled to one log per model per hour. Semantic search returns 503 when the embedder is disabled. Model-family prompt formats live in `queryText` / `documentText`: nomic-embed models get `search_document:` / `search_query:` prefixes, qwen3-embedding models get an `Instruct:`/`Query:` line on the query side only, other models get raw text. `NewEmbedder(url, model, timeout)` resolves explicit args, then `MEMSTATE_EMBEDDING_URL` (old name `MEMSTATE_OLLAMA_URL`, still read with a notice) / `MEMSTATE_EMBED_MODEL` / `MEMSTATE_EMBED_TIMEOUT`, then defaults (the 60s timeout exists because a 4B model cold-loads in ~20s, which the old 10s bound cut off); the daemon exposes both as `--embedding-url` / `--embed-model` and reports them in `/health` (`embedding_url`, `embed_model`), which the proxy checks against its own env on attach; `/health` also carries `semantic_threshold`, and `memstated embed status` reads both from the running daemon (`runningEmbedConfig`) unless overridden by flag or env. On startup `BackfillEmbeddings` eagerly embeds every current keypath missing a vector for the configured model (sequential, aborts on first transport error — the next startup or per-write heal retries). `Backfill` is the synchronous core; `Rebuild` = delete the model's rows + `Backfill`. Tests use `Embedder.WaitForPending()` for determinism — production never waits.

## Conventions (non-obvious)

- **No co-authoring on commits.** Do not add `Co-Authored-By:` trailers.
- New tool → edit three places in lockstep: `server/http.go` (route + handler), `client/src/index.ts` (`TOOLS` entry), `client/skill/scripts/` (Python CLI). The skill scripts are a supported interface, not a legacy artifact.
- `client/skill-precompact/SKILL.md` is a second, user-invoked skill (`/memstate-precompact`): before a `/compact` it has the agent write the session state to memstate (task.summary.<date>, decisions.*, gotchas.*, todo, questions, notes.*) and print the `/compact` argument line that names those keypaths. It ships with the memstate skill: `make install-skill`, both install scripts, the release bundle (`skill-precompact/`) and the CI `install-scripts` assertions must stay in step.
- `SKILL.md` in `client/skill/` now describes THIS daemon accurately (integer IDs, synchronous writes, headings-only extraction, category/topics filterable) and is the canonical statement of naming conventions (snake_case ids/segments, YYYY_MM_DD dates, `branches.<slug>.*` for branch-scoped state). Keep it, the MCP `INSTRUCTIONS`/tool descriptions in `client/src/index.ts`, and the Python `--help` strings in agreement when conventions change.
- `.claude/hooks/memstate-persist-reminder.sh` runs on `UserPromptSubmit` and nudges toward `memstate_remember` after ≥3 file edits since the last persist. If you want to silence it for a session, touch a trivial `memstate_set` or `memstate_remember` call.
- `.claude/hooks/memstate-recall.sh` runs on `UserPromptSubmit` and execs `memstated recall` (`server/recall.go`): hybrid-search the project derived from the hook's `cwd` (same slug rule as the proxy and the Python skill, pinned by `TestDeriveProject`) with the prompt text, print up to 3 unseen hits at 500 chars each inside `<memstate-recall>`, and record them in `~/.memstate/recall/<session_id>` so a keypath is injected once per session (files older than 7 days are pruned). It needs a **shared** daemon: `MEMSTATE_ADDR`, else `daemon.addr`; child-mode daemons are invisible to it. Before the search it reads `/health` and, when the daemon's `version` or `build` differs from its own `healthVersion` / `buildID()` (the short git revision Go embeds, `+dirty` when the tree was modified; `server/build.go`), prints a one-time `<memstate-notice>` (`versionSkewBlock`, seen-file marker `#version`) that asks for a daemon restart; the notice is printed even when the search then fails, because a daemon on another version rejects `include_content` (400) or returns hits without content, and both are otherwise silent. Prompts under 4 words are skipped, `MEMSTATE_NO_RECALL=1` disables it, `MEMSTATE_RECALL_DEBUG=1` explains a silent exit on stderr. It always exits 0. `make install-skill` installs both hook scripts; `scripts/configure-claude-hook.py` strips and re-adds every entry that names one of its `MARKERS`.
- Formerly accepted-but-ignored fields: `category`/`topics` are now stored and filterable; `at_revision` and `context` were dropped and are rejected by `DisallowUnknownFields`. Do not add silently-ignored request fields — accept a field only when it does something.
- **`memstate` is the human CLI** (`server/cli.go`), the same binary as the daemon: `make install` links `$(GOBIN)/memstate → memstated` and `main()` dispatches on `filepath.Base(os.Args[0])`, so the link never starts a daemon (`memstated <verb>` also works). Verbs: `tree`, `get`, `history`, `search`, `set`, `edit`, `rm`, `projects`, `status`. Project defaults to the cwd repo slug (`deriveProject`), `--user` targets `_user`, `--json` prints raw shapes, flags may follow positionals (`parseInterspersed`). Reads open SQLite directly (`openStoreCLI`); `search` asks the shared daemon (hybrid) and falls back to `Store.SearchAny` with a "fts only" note; `set`/`edit`/`rm` require the daemon (`openDaemon` → `discoverAddr`) so embeddings and the `_user` gate apply. `edit` runs `$VISUAL`/`$EDITOR` on a temp file and keeps the previous category/topics. `rm --recursive` needs a y/N answer or `--yes` (mandatory when stdin is not a TTY). `memstated dump|search` are aliases (`dump PROJECT` = `get --project PROJECT`, `--keys` = `tree`); `search` now defaults to the cwd project, `--all` for the whole store. ANSI markdown highlighting lives in `server/dump.go` (`palette`, `renderMarkdown`, `printEntry`, `printKeyTree`), off when stdout is not a TTY or `NO_COLOR`/`--no-color` is set. Tests swap `cliOut`/`cliErr`/`cliIn`. Do not add HTTP routes or MCP tools for these; the model has `memstate_get`/`memstate_search`.
- **Releases & self-upgrade:** `healthVersion` in `server/main.go` is the single version source; CI (`.github/workflows/build.yml`) refuses a `v*` tag that doesn't match it, then publishes raw platform binaries (`memstated-<os>-<arch>[.exe]`, built by `make release`) as GitHub release assets, plus `memstate-mcp.tar.gz`: `make release` stages it in `tmp/bundle` (client `package.json`/lock/LICENSE/`dist` with `npm ci --omit=dev` node_modules, pure JS so one file serves every platform; `skill/`, `hooks/`, `configure-claude-hook.py`). `install.sh` (Linux, macOS) and `install.ps1` (Windows PowerShell 5.1+) fetch the binary and the bundle from one tag and unpack both into a root that mirrors the repo (`<root>/server/memstated`, `<root>/client/dist/index.js`), so `resolveDaemonBin`'s sibling rule finds the daemon without PATH; they run a hermetic `--test`, then `memstate-mcp setup` in a terminal, then ask about the skill (`MEMSTATE_SETUP`, `MEMSTATE_INSTALL_SKILL` answer without a prompt; `MEMSTATE_DOWNLOAD_URL` is the test seam the `install-scripts` CI job uses). Never install the proxy by npm name: `@memstate/mcp` on npm is the upstream client this repo forked, and `npm update -g` would swap it in. `memstated upgrade` (`server/upgrade.go`) downloads the matching asset over the current executable and stop-swap-restarts a shared daemon; before stopping it reads `/health` (`fetchHealth`) and `restartPlan` replays the old daemon's `args` while env and config.env supply the rest, and `reportRestartDiff` prints any embed or idle setting that changed, so an upgrade never *silently* reverts a model or threshold (it did once, 2026-09-06, and again on 2026-10-09 when an installer rewrote the agent args, which is why settings moved to config.env). `memstated restart` is the same path without the download. Asset names must stay in sync across `releaseAssetName()`, the Makefile `release` target and both install scripts. The daemon checks the releases API on startup + daily (`watchUpdates`) and nudges via a stderr line + `latest_available` in `/health`; `MEMSTATE_NO_UPDATE_CHECK` disables it (tests set it — hermetic daemons must not touch the network).
- **`memstated embed status|rebuild|prune` is CLI-only** (`cmdEmbed` in `server/main.go`, direct SQLite like dump/export; the status dashboard lives in `server/embedstatus.go`: `collectEmbedStatus` gathers, `renderEmbedStatus` prints, `similarityStats` samples up to 500 vectors for the pairwise cosine histogram and nearest-neighbour percentiles that guide `MEMSTATE_SEMANTIC_THRESHOLD`). Vectors are keyed by model name, so several sets coexist; `rebuild` rewrites one model's set from scratch, `prune` drops all others. Do not add an HTTP route or MCP tool for this.
- **Export/import is deliberately CLI-only** (`memstated export|import`, direct SQLite access in `server/export.go` + `server/main.go`). It's a human cross-machine workflow; do NOT add an MCP tool or HTTP route for it. Import merges by timestamp: keypaths absent locally get their full version history copied; existing keypaths take the file's latest value only when it is strictly newer (replayed through the normal write path, so dedupe/supersede/tombstone semantics apply and re-imports are no-ops). `import --force` skips the timestamp comparison so the file's latest always wins (identical state still dedupes).

## Where data lives

| Thing | Path |
|---|---|
| Settings file | `~/.memstate/config.env` (env `MEMSTATE_CONFIG`; `off` skips it); `KEY=VALUE` lines of the names below, read by daemon, proxy and scripts |
| SQLite DB | `~/.memstate/memstate.db` (env `MEMSTATE_DB`; `~/` is expanded) |
| Daemon log | `memstated.log` next to the DB (default `~/.memstate/memstated.log`; `daemonLogPath`, `openDaemonLog`, `_client._memstate_dir`) |
| Programs (install script) | `${XDG_DATA_HOME:-~/.local/share}/memstate` with links in `~/.local/bin` (`MEMSTATE_INSTALL_DIR`); Windows `%LOCALAPPDATA%\Programs\memstate`, `server\` on the user PATH |
| Shared daemon address | `~/.memstate/daemon.addr` (next to the DB; written by a `--addr` daemon at startup, removed on shutdown; `discoverAddr()` reads `MEMSTATE_ADDR` first, then this file, and trusts the file only when `/health` answers) |
| Embedding URL | `http://127.0.0.1:11434` (env `MEMSTATE_EMBEDDING_URL` or `--embedding-url`; a URL ending in `/v1` is an OpenAI-compatible server; old name `MEMSTATE_OLLAMA_URL` / `--ollama-url` still read) |
| Embed model | `nomic-embed-text` (env `MEMSTATE_EMBED_MODEL` or `--embed-model`) |
| Embed timeout | `60s` per embedding call (env `MEMSTATE_EMBED_TIMEOUT` or `--embed-timeout`; must cover a cold load of a large model) |
| Semantic threshold | `0.5` (env `MEMSTATE_SEMANTIC_THRESHOLD` or per-request) |

Daemon binds loopback only. In attach mode, `MEMSTATE_DB` on the proxy is silently ignored (the running daemon picked its DB at startup) — the proxy emits a warning.
